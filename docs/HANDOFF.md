# Передача контекста: что уже сделано и почему

Сводка диалога со старостой (владельцем бота), в котором бот был написан с нуля.
Нужна, чтобы продолжить работу в новой сессии Claude Code — например, на сервере.

## Кто пользователь и что ему нужно
Староста учебной группы (в примере ведомости — «УФРС24-2»). Пишет по-русски, не
программист. Бот уже запущен у него на своём сервере в Docker рядом с другим
(музыкальным) Telegram-ботом. Ему важно: простота для одногруппников, ведомость
в Excel «как бумажный журнал», надёжность (бэкапы).

## Хронология запросов и решений
1. **Базовый бот.** Сообщение в группе по расписанию, личная админ-панель старосты:
   статистика по дням, настройки, расписание (дни недели, разовые даты, пропуски-праздники).
2. **Текст, режимы, время, состав, защита.**
   - Редактируемые заголовок/текст/кнопка, подстановки `{дата} {день} {время} {до}`.
   - Режим «на каждой паре» / «раз в день».
   - Время работы кнопки: N минут, до времени, до конца дня, без ограничения;
     применяется и к открытой отметке.
   - Состав группы: Bot API не отдаёт участников, поэтому через Telethon (MTProto от
     имени бота) при наличии `API_ID`/`API_HASH`; без них — админы чата, кто пишет/заходит,
     кнопка регистрации. При добавлении бота старостой — автопривязка.
   - Защита: только участники чата (`getChatMember`), нажатия с копий в других чатах
     отклоняются, `protect_content`, режим «только из списка».
3. **«Я болею».** Кнопка открывает личку (deep link `?start=sick`), календарь первого и
   последнего дня или ввод текстом; больничные в статистике и Excel.
4. **Месяцы и Excel.** История по месяцам; CSV заменён на .xlsx по образцу файла старосты
   (проверено: клетки совпали с оригиналом 1:1); дата всегда в сообщении.
5. **Сообщество с несколькими чатами / темами.** `/bind` в нужной теме форума
   (`message_thread_id`); добавление бота во второй чат больше не перепривязывает.
6. **Баг: «Удалить занятие» бесконечно грузилось.** Причина — необработанная ошибка
   Telegram при удалении сообщения (миграция группы → супергруппы / бот удалён).
   Исправлено: сначала удаляем из БД, сообщение — по возможности; общий обработчик
   ошибок на `dp.errors`; миграция чата переносит занятия на новый ID.
7. **Логика перевёрнута: «🚫 Пропускаю» вместо «✅ Я был».** Жмут только отсутствующие,
   остальные из списка — присутствовали. Таблица `absences`; старые данные мигрированы
   (кто не нажал «Я был» → пропуск). Правило статуса — в `bot/stats.py`.
8. **Резервные копии.** Ежедневно в 23:00 (настраивается) старосте в личку `.db` + `.xlsx`;
   восстановление из файла через админку с предпросмотром и копией текущих данных.

## Что НЕ проверено в реальном Telegram
Все тесты (`pytest`, 32 шт.) проходят на фейковом Telegram, но в живом чате не проверены:
- считывание участников через Telethon (`bot/members.py::fetch_all_members`);
- привязка к теме форума и поведение `protect_content`;
- пересчёт формулы ИТОГО в Excel (LibreOffice в облачной среде зависал; формула та же,
  что в файле старосты, `fullCalcOnLoad=True`).
Если владелец сообщает об ошибке — первым делом `docker compose logs --tail 100`.

## Возможные следующие шаги (предлагались, но не заказаны)
- Импорт ФИО из Excel-списка старосты с автосопоставлением аккаунтов Telegram
  (сейчас ФИО задаются переименованием студента в карточке).
- Значение «Кнопка активна» по умолчанию — 90 минут; при логике «Пропускаю» старосте
  советовали «до конца дня» или «до определённого времени».
